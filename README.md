# Alarms — один будильник, четыре реализации

Здесь лежит одно и то же приложение — настольный будильник в стиле «Часов» от Apple, — написанное четыре раза. Стеки разные, и архитектура у каждой реализации своя.

**Что умеет приложение и как выглядит** — единый документ для всех четырёх: [`ALARM_SPEC.md`](ALARM_SPEC.md). Скриншоты к нему лежат в [`docs/screens/`](docs/screens/). Реализации должны совпадать со спецификацией практически 1 в 1. Отличаться они могут только тем, что зависит от платформы.

## Что умеет приложение

Коротко; подробно и с точными числами — в [`ALARM_SPEC.md`](ALARM_SPEC.md).

- **Будильники.** Время, повтор по дням недели, название, вкл/выкл переключателем. Список отсортирован по времени, вверху — сколько осталось до ближайшего звонка.
- **Мягкий звонок.** Громкость плавно нарастает от почти полной тишины за выбранное время: от 15 секунд до 10 минут, или сразу на полную.
- **Звуки.** 6 встроенных мелодий или свой аудиофайл (MP3, M4A, WAV, OGG, FLAC и др., до 80 МБ). Файл копируется внутрь приложения.
- **Выключение с заданием.** Чтобы выключить будильник, нужно решить пример или перепечатать код: от 1 до 5 подряд, три уровня сложности. Задание можно и не ставить.
- **Отсрочка (Snooze).** На заданное число минут, сколько угодно раз и без задания: с экрана звонка, из системного уведомления, а в нативных версиях ещё и из меню в трее.
- **Экран звонка.** На весь экран, всегда тёмный: крупное время, дата и кнопки `Snooze` и `Stop`.
- **Надёжность.** Звонок переживает перезапуск. Если компьютер спал, будильник прозвонит после пробуждения, а если опоздание слишком большое — пришлёт уведомление о пропущенном. Опция `Keep Computer Awake` не даёт компьютеру уснуть, пока есть включённые будильники. Нативные версии звонят и при закрытом окне и запускаются вместе с системой.
- **Таймер.** Барабаны для часов, минут и секунд, кольцо прогресса, пауза, свой звук и список недавних таймеров.
- **Секундомер.** Сотые доли секунды, круги с подсветкой лучшего и худшего, клавиши `Space` и `L`.
- **Настройки.** Тема (`Auto`, `Light`, `Dark`), формат времени 12/24 ч, значения по умолчанию для новых будильников, длина отсрочки.
- **Офлайн и приватно.** Без сети, облака и аккаунтов. Все данные хранятся на компьютере, у каждого пользователя ОС свои.
- **Дизайн.** Как у приложения «Часы» от Apple: сгруппированные списки, барабаны выбора, всплывающие панели (sheets), круглые кнопки, тёмная и светлая темы.

## Реализации

| Папка | Стек | Архитектура | Звонит при закрытом окне |
|---|---|---|---|
| [`alarm/`](alarm/) | React + Vite, PWA | Feature-Sliced: слои `app → features → shared` | нет (ограничение браузера) |
| [`alarm-electron/`](alarm-electron/) | Electron + чистый JavaScript | события и журнал, несколько процессов; клиент — MVU (как в Elm) без фреймворка | да |
| [`alarm-rs/`](alarm-rs/) | Rust: демон + Tauri и Leptos | порты и адаптеры, отдельный демон; клиент — тонкий, на реактивных сигналах Leptos | да |
| [`alarm-py/`](alarm-py/) | Python + Qt Quick (PySide6) | акторы с супервизором, один процесс; клиент — MVVM (QML + ViewModel) | да |

Склонировать репозиторий и перейти в него:

```bash
git clone https://github.com/B1aho/alarms.git && cd alarms
```

Все команды ниже запускаются из корня репозитория.

## `alarm/` — эталон на React

**Стек:** React 19, Vite, TypeScript, TanStack Router, Tailwind CSS, IndexedDB.

**Архитектура.** Веб-приложение, разложенное по фичам: Alarms, Timer, Stopwatch и Settings — отдельные модули, а общий код (звук, хранилище, компоненты) лежит в `shared`. Фичи не знают друг о друге; это правило проверяет свой линтер. Будильник звонит, пока вкладка открыта. Закрытый браузер — главное ограничение веба, из-за которого появились нативные версии.

```bash
cd alarm && npm install && npm run dev
```

Откроется на http://localhost:5173.

## `alarm-electron/` — события и журнал

**Стек:** Electron, чистый JavaScript без фреймворка и без сборщика, Web Audio, Playwright для тестов.

**Ядро.** Приложение — несколько процессов, которые общаются только сообщениями:
- **главный процесс:** трей, окна, уведомления;
- **движок:** хранит всё состояние и решает, когда звонить;
- **невидимый процесс звука;**
- **окно:** живёт, только пока открыто.

Состояние не перезаписывается, а копится как журнал событий («будильник сохранён», «будильник зазвонил»). Текущее состояние — это результат проигрывания журнала, поэтому звонок переживает перезапуск.

**Клиент.** Окно устроено как в Elm (MVU) и не использует фреймворк. Всё, что видно на экране, описано одним объектом-моделью. Любое действие пользователя или событие от движка — это сообщение. Чистая функция `update` получает модель и сообщение и возвращает новую модель плюс список эффектов (например, «отправить команду движку»). Функция `view` строит из модели виртуальное дерево, а свой маленький `patch` переносит разницу в DOM. Своё состояние держит только барабан выбора времени (Web Component с физикой прокрутки): наружу он отдаёт лишь выбранное значение.

```bash
cd alarm-electron && npm install && npm start
```

## `alarm-rs/` — порты и адаптеры

**Стек:** Rust. Демон на `tokio`, SQLite, звук через `rodio`. Окно — Tauri, а интерфейс в нём тоже на Rust (Leptos, компилируется в WebAssembly).

**Ядро.** Это две программы:
- **фоновый демон `alarmd`:** всегда работает, звонит, хранит данные, держит значок в строке меню. Если демон упадёт, система перезапустит его сама;
- **окно `alarm-ui`:** запускается, только когда нужно показать интерфейс.

Внутри демона — чистое ядро, которое ничего не знает об операционной системе. Время, диск, звук и уведомления подключены к нему через интерфейсы («порты»), а реализации («адаптеры») лежат в отдельных крейтах. Границы между ними проверяет компилятор.

**Клиент.** Тонкий клиент, который ничего не решает. Демон после каждого изменения присылает полный снимок состояния, а клиент только рисует его и отправляет обратно команды («сохранить будильник», «отложить»). Даже ответы на задания при выключении проверяет демон. Окно Tauri — лишь ретранслятор между сокетом демона и WebView. Сам интерфейс написан на Leptos и построен на реактивных сигналах. Снимок от демона лежит в сигнале, и при его смене пересчитываются только привязанные к нему узлы DOM. Виртуального DOM и общего цикла «модель → обновление → отрисовка», как в Electron, здесь нет. Локально клиент хранит только состояние экрана: черновик в редакторе, открытую подстраницу, режим Edit.

```bash
cd alarm-rs && cargo xtask dev
```

Нужны `trunk`, `tauri-cli`, `wasm-bindgen-cli` и цель `wasm32-unknown-unknown` (подробнее — в [`alarm-rs/README.md`](alarm-rs/README.md)). Первая сборка долгая.

## `alarm-py/` — акторы

**Стек:** Python 3.13, PySide6 (Qt Quick / QML), акторы на `pykka`, звук через `sounddevice` и PyAV, окружение `uv`.

**Ядро.** Один процесс, живущий в трее. Каждая обязанность — часы, будильники, диск, звук, уведомления, запрет сна — это отдельный «актор» в своём потоке со своим почтовым ящиком. Акторы не вызывают друг друга, а пересылают сообщения. Если какой-то упал (например, отвалилось аудиоустройство), супервизор перезапускает его, и расписание при этом не останавливается.

**Клиент.** MVVM на Qt Quick, три слоя:
- **QML** — разметка, анимации и физика барабана, без логики;
- **ViewModel** — Python-объекты со свойствами и слотами. QML привязывается к свойствам и сам перерисовывается при их изменении. ViewModel хранит только состояние экрана (черновик редактора, открытую подстраницу, режим Edit), а сводки и форматы берёт из общих правил;
- **мост `UiBridge`** — единственная связь с акторами. События из потоков акторов он превращает в сигналы главного потока Qt, а команды из ViewModel отправляет акторам, никогда не дожидаясь ответа, чтобы окно не подвисало.

Окно и его ViewModel создаются при открытии и уничтожаются при закрытии; акторы при этом продолжают работать.

```bash
cd alarm-py && uv run alarm
```
